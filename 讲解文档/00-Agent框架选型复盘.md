# 00 · Agent 框架选型复盘：从 AgentScope 到自研手写

> 这是 ADR-001 的"过程版"。结论只有一句话——**Agent 层不引框架，手写**——但值钱的是这一路怎么推出来的。下次你做任何技术选型，都可以把这篇的推理路径再走一遍。

## 1. 事情的起点是一次"不安"

v1.3 定了 AgentScope（Globex 同款，锁版 2.0.8）。但有个声音一直在："这东西是不是太小众了？"——注意，**不安本身就是尽调信号**。它值得被认真对待，方法是把它转成可验证的问题：

- AgentScope 在 2026 年 9 月的社区体量到底如何？
- 我的真实需求是什么？框架在其中承载了多少？

## 2. 先把"真实需求"问出来

复盘原始诉求，最后浮出的是这句：**"我想做一个比较厉害、有上下文管理、记忆、成本控制，和 Claude 功能差不多的 Agent。"**

这句话改变了整个局面。因为它意味着：

- 我要学的是 **harness 这一层本身**（上下文/记忆/成本是 harness 的组件），而不是"用某个框架拼一个应用"；
- 框架对这三种能力的态度是"替你做掉"——AgentScope/LangGraph 的记忆与上下文抽象会替你做决定，**你学到的是它们的 API，而这层恰恰是你要学的东西**。黑盒把课程内容包走了。

## 3. 再量化"框架承载量"

数一数这个项目里谁真的在走 agent loop：

| 用例 | 走不走 loop | 原因 |
| --- | --- | --- |
| P2 识别+提取 | ❌ 单次结构化调用 | 快、省、可测（架构边界已定） |
| P4 材料生成 | ✅ 一个 ReAct 循环挂 3-4 个工具 | 需要边查边写 |
| P5 学习路径 | ✅ 一个循环挂 search+校验 | 需要边搜边引用 |

**结论：框架承载量 ≈ 两个循环 + 几个工具 ≈ 手写 150-200 行。** 一个只承载这么少的依赖，"小众"的代价（资料少、版本变动大、面试不认）却要全额支付——这买卖不划算。

## 4. 候选全景与尽调三问

对每个候选问三件事：**谁维护的？协议/授权允许吗？出了问题社区能不能救你？**（2026-09 实查）

| 候选 | 维护方 | 社区 | 关键判断 |
| --- | --- | --- | --- |
| AgentScope 2.x | 阿里，活跃 | 二梯队；0.x→1.x→2.x **三次破坏性重写** | 网上资料极易和你的版本对不上 |
| LangGraph | LangChain 公司 | 生产记录最强 | 对单循环是牛刀；**v2 若需框架的候选之一** |
| Pydantic AI | Pydantic 官方 | 快速上升，文档口碑最好 | 轻量类型安全；**v2 若需框架的首选** |
| OpenAI Agents SDK | OpenAI | 大但偏 OpenAI 系 | 与"多模型档案热切换"诉求不顺 |
| Claude Agent SDK | Anthropic | 官方 | **有 Python 版**！但一等公民是 Claude 模型，接 DeepSeek 非官方路径 → 要么绑 Anthropic（国内访问+付费+推翻模型决策），要么用第三方复刻（法律风险） |

**教训一：Claude Agent SDK 有 Python 版这个事实，是查了才知道的。** 直觉（"它是 TS 的所以不关我事"）和事实（官方 Python SDK 存在但模型绑定）是两回事，选型要查证不要猜。

## 5. 中途认真考虑过的岔路：TS harness 包装

"能不能后端 Python，Agent 层用 deepseek-harness 或 claude code，中间包一层？"——技术上完全可行（子进程/HTTP sidecar/MCP 桥），认真算过四笔账后被否：

1. **胶水账**：harness 是库不是服务。要包，得自建 TS sidecar + JSON 协议 + 进程管理 + 错误/流式桥接——几百行 TS 胶水，只为省 150 行 Python 循环。负 ROI。
2. **工具账**：本项目的工具全是 Python 领域逻辑（bs4 爬虫、SQLite 仓储、带降级搜索）。跨语言意味着每个工具要么写两份，要么再挂一层 MCP 桥——三个活动部件伺候三四个工具。
3. **部署账**：P6 验收是"同学按 README 10 分钟跑通"。加 Node 运行时 + npm + 双进程编排，Windows 同学当场退群。
4. **救援账**："Python 包 TS harness"这个组合全网没有第二个人这么用。尽调第三问"社区能不能救你"——救不了，孤本是没人救的。

**教训二：这种"通用 harness + 桥接"模式并不是错的**——当工具天然通用（shell、文件系统，比如 CI 里自动修 issue）时它反而是正解。它只是和"领域绑定工具"的项目形状不匹配。**没有错误的模式，只有错配的形状。**

## 6. 最终决策与它的三层含义

**决策：`application/harness/` 手写 loop + 工具注册表 + skill 加载器；v2 沿三条主线长成 mini-harness。**

- 对产品：零框架依赖，钉版焦虑清零；
- 对学习：上下文管理 = token 计量+阈值摘要；记忆 = markdown 文件+注入；成本控制 = 台账+预算+路由。每样都是百行级组件，逐行拥有它们；
- 对复刻 Globex：**复刻的是架构纪律（四层/装配根/settings/端口），不是 agent 库**。映射表只动一行，学习价值不减反增（多了一篇 ADR 和一个"为何不用 X"的经典选型案例）。

## 7. 风险与兜底

自研 = 质量责任在自己。兜底三件套：**trace 日志**（每轮 prompt/工具/结果落盘，可回放）、**v2 评测套件**（改 prompt 后跑回归）、**端口隔离**（harness 局部化在 `application/harness/`，若 v2 agent 面扩大，换 Pydantic AI 只动一个目录）。
