## 没写 ADR 但同样重要的取舍

- **SSE 而非 WebSocket**：对话是"一问一答的流式生成"，SSE 语义刚好且纯 HTTP；
  真需要双向实时（实时终端/协作）再上 WebSocket；
- **静态导出而非 next start**：保住 FastAPI 单端口部署模型；代价是没有 SSR，
  但本项目全是交互界面，无 SEO/首屏诉求；
- **手写 CSS → Tailwind 的迁移**：M4-M10 手写令牌 CSS 是为了学设计体系；
  M11 迁 Tailwind 是为了与 TeachX 形态对齐——两段经历都是刻意的；
- **权限门而非沙箱**：工具都是自写的有界能力，按名单挑敏感工具管理即可；
  引入 shell 类"大权"工具时再上沙箱（两条路不冲突）；
- **SQLite 而非 Postgres**：单机单用户，SQLite 的零运维完胜；仓储层有
  可迁移性参数化测试（文件库/内存库），换库时业务层零改动。
