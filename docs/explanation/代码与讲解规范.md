# 代码与讲解规范（Explanation）

> 本项目同时是教材：代码和讲解文档都会被逐行阅读。所有贡献（包括 AI 生成）
> 统一按"偏小白读者"的标准写。此规范长期有效，原出处为开发日志 §15。

1. **代码风格**：宁可啰嗦，不可炫技。不为了简洁/美观引入复杂写法（嵌套推导式、
   一行流、花哨装饰器链）；变量名写全不缩写；功能正确性永远优先于风格。

2. **注释覆盖**：关键模块写详细注释（是什么 / 为什么 / 怎么用）；基础代码哪怕
   是 CRUD 也至少有一句话说明这里在做什么；注释语言小白友好，优先用后端概念
   类比（Java 的 interface / Bean / Spring 容器 / JDBC）。

3. **高级语法不禁用，但必须配注释**：Protocol、lru_cache、dataclass、property
   这类写法出现时，旁边必须解释"这是什么、为什么用它"。

4. **讲解文档风格**：小白友好但不幼稚；类比与举例优先对齐真实 Agent 产品
   （Claude Code 等）与主流工程实践，不用生造的例子。

5. **提交前检查**：`uv run pytest` 全绿；改了识别相关逻辑必跑 `uv run sai eval`
   （见 how-to/跑识别评测防退化.md）；提交信息遵循 Conventional Commits。

6. **文档纪律**：每完成一个阶段写一篇讲解文档（为什么 > 怎么做 > 踩坑）进
   Obsidian 讲解库；重大取舍立 ADR 进 `docs/adr/`；面向使用者的操作知识
   沉淀进 `docs/how-to/`。
