### 2.2 Agent 框架尽调（2026-09-30，v1.4 依据）

| 候选 | 2026-09 实况 | 结论 |
| --- | --- | --- |
| AgentScope 2.x | 阿里出品、活跃、Apache 2.0，但社区二梯队；0.x→1.x→2.x 三次破坏性重写 | 弃用：本项目 agent 面极小，框架收益覆盖不了版本变动与"小众"成本 |
| LangGraph | 生产环境记录最强、事实标准 | 不选：对"单个 ReAct 循环"是牛刀；简历需求出现时 v2 再评估 |
| Pydantic AI | Pydantic 官方，轻量、类型安全、文档最佳、快速上升 | v2 若引框架的首选 |
| OpenAI Agents SDK | OpenAI 官方，极简 | 不选：生态偏 OpenAI 系，与多模型档案诉求不顺 |
| Claude Agent SDK | **有官方 Python 版**，但一等公民是 Claude 模型（Bedrock/Vertex），接 DeepSeek 非官方路径 | 不选：要么绑 Anthropic（国内访问+付费+推翻 DeepSeek 决策），要么回到有法律风险的第三方复刻 |

**TS harness 包装路线否决（Python 后端 + 子进程/MCP 调 TS harness）**：① harness 是库不是服务，胶水层（TS sidecar+协议+进程管理）比省掉的 150 行 loop 厚；② 工具全是 Python 领域逻辑，跨语言双份或 MCP 三件套；③ P6"同学 10 分钟跑通"验收翻车；④ 自建集成无社区可救。**该模式只在工具天然通用（shell/文件系统）时才对。**

## 3. 项目定义

自动盯学校官网 → 识别比赛 → 提取比赛卡片（含原文证据）→ 交付物型按 Skill 生成材料（PPT 大纲/计划书/稿子）、考试型生成强制真实引用的学习路径（引用存在性校验防幻觉）。

架构边界：识别/提取走**单次结构化调用**（快、省、可测）；生成材料与学习路径走**手写 harness 的 ReAct 循环**。

## 5. 架构总纲：分层映射

沿 Globex 的分层纪律与装配方式；Agent 库由 AgentScope 换为自研 harness，其余映射不变。

| Globex（参照物） | 本项目 contest_agent |
| --- | --- |
| `app/domain/` 纯领域模型 + ports | `domain/`：`entities.py`（Notice、Competition）+ `ports.py`（NoticeSourcePort、CompetitionRepositoryPort、LlmPort、SearchPort） |
| `app/application/` agents/tools/usecases | `application/usecases/`（scan_site、identify_competitions、generate_report、generate_material）+ `application/harness/`（**AgentScope 接驳层 agent_factory + 技能加载器**）+ `application/tools/`（工具构建器） |
| `app/infrastructure/` llm/persistence/... | `infrastructure/crawler/`（实现 NoticeSourcePort）+ `infrastructure/llm/`（openai 兼容工厂，DeepSeek 档案）+ `infrastructure/persistence/`（SQLAlchemy 模型与仓储）+ `infrastructure/search/` |
| `app/presentation/` FastAPI server | `presentation/server.py`（/health /scan /competitions /generate）+ `presentation/cli.py`（sai 薄壳） |
| `app/composition.py` 装配根 | `composition.py`：settings → 爬虫 → LLM 工厂 → 仓储 → 用例 → app，单向装配 |
| `app/infrastructure/settings.py` 环境优先 | `settings.py`：env > config.yaml > 默认值；密钥只存环境变量名 |
| Globex prompts/capability 加载 | `skills/*.md` 自研加载器（frontmatter + 步骤） |
| Globex eval harness | v2 提取质量评测套件（借鉴 deepseek-harness 与 pi 的遥测契约思想） |
| 钉版策略 | agentscope==2.0.8、sqlalchemy>=2.0,<3、fastapi>=0.115 |

## 6. 存储与上架分析

- v1：SQLAlchemy ORM + SQLite；`notices` / `competitions` 两表，幂等键 = 来源 URL + 标题哈希

## 15. 代码与讲解规范（2026-09-30 新增，长期有效）

本项目同时是教材：代码和讲解文档都会被逐行阅读。统一按"偏小白读者"的标准写：

1. **代码风格**：宁可啰嗦，不可炫技。不为了简洁/美观引入复杂写法（嵌套推导式、一行流、花哨装饰器链）；变量名写全不缩写；功能正确性永远优先于风格。
2. **注释覆盖**：关键模块和关键功能写详细注释（是什么 / 为什么 / 怎么用）；基础代码哪怕是 CRUD 也至少有一句话说明这里在做什么；注释语言小白友好，优先用后端概念类比（Java 的 interface / Bean / Spring 容器 / JDBC）。
3. **高级语法不禁用，但必须配注释**：Protocol、lru_cache、dataclass、property 这类写法出现时，旁边必须解释"这是什么、为什么用它"。
4. **讲解文档风格**：小白友好但不幼稚；类比与举例优先对齐真实 Agent 产品（Claude Code 等）与主流工程实践，不用生造的例子。
